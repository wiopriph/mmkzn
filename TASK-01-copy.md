## Режим работы

**Не задавай вопросов.** Если чего-то не хватает — прими самое консервативное разумное решение, запиши его строкой в `DECISIONS.md` в формате `дата · что решил · почему · что перепроверить` и продолжай. Останавливайся и пиши мне только в трёх случаях:

1. Старый сайт недоступен или REST API закрылся — без него задача не выполнима.
2. Скрипт выгрузки падает второй раз подряд после твоей правки.
3. Ты собираешься удалить или перезаписать файл, который создал не ты.

**Не спрашивай разрешения на рутину.** Ставить пакеты, создавать файлы, запускать сборку, переписывать собственный код — делай молча.

**Проверяй себя сам.** После каждого шага запускай проверку из этого документа. Шаг не закрыт, пока проверка не зелёная. Не переходи дальше со сломанным состоянием и не пиши «потом поправлю».

**Коммить по шагам.** Один шаг — один коммит с осмысленным сообщением. Так я смогу посмотреть, где ты свернул не туда.

**В конце отчитайся кратко:** что сделал, что решил за меня (список из `DECISIONS.md`), что не сошлось, что осталось.

## Что значит «перенести сайт»

Итог задачи: на новом стеке открываются все страницы старого сайта, **по тем же адресам, с тем же содержимым и той же мета-разметкой**, и выглядят они **похоже на оригинал — но не идентично**.

Разберём это точно, потому что здесь легко переусердствовать.

**Обязано совпадать байт в байт:**
- URL всех страниц, включая уродливые Yoast-слаги с `cz` — `/pesok-rechnoj/`, `/shheben-izvestkovyj-frakczionnyj-20-40/` и остальные;
- `<title>` и `<meta name="description">`;
- тексты, заголовки, их порядок;
- **цифры в таблицах характеристик.** Это данные лаборатории. Не округляй, не переформулируй, не «приводи к единому виду», не заполняй пропуски по смыслу.

**Должно быть похоже, но своё:**
- порядок и смысл секций на странице — тот же (шапка, герой, о нас, услуги, преимущества, прайс, галерея, контакты, подвал);
- тип блока — тот же: сетка остаётся сеткой, таблица таблицей, галерея галереей;
- пропорции крупных элементов — примерно те же.

**Специально должно отличаться:**
- цвета, шрифты, отступы, тени, скругления — твои, из `tokens.css`;
- вёрстка — Tailwind v4 и flex/grid, ни строчки CSS старой темы;
- разметка — семантическая и чистая.

**Чего категорически не делай:**
- не копируй CSS темы WordPress и не подключай его;
- не рендери сырой HTML старого сайта через `v-html`;
- не гонись за пиксельным совпадением — если блок отличается на 20 пикселей, это правильный результат, а не дефект;
- не изобретай секции, которых на старом сайте нет;
- не переписывай тексты клиента «чтобы звучало лучше».

Ориентир по усилиям: **вся вёрстка десяти страниц — это работа на один заход, а не на неделю.** Всё это будет заменено редизайном. Задача копии — сохранить контент, адреса и позиции в поиске, а не получить красиво.

## Шаг 3. Выгрузка

```bash
pnpm dlx tsx scripts/extract-wp.ts --all
```

Скрипт готов, он проверен против живого REST API этого сайта. **Не переписывай его.** Если падает — почини минимально, опиши правку в `DECISIONS.md`.

Дальше, если на машине есть Playwright, сними референсы:

```bash
pnpm add -D playwright && pnpm exec playwright install chromium
pnpm dlx tsx scripts/extract-wp.ts --shots
```

Скриншоты в `data/extracted/shots/` — твой единственный ориентир по вёрстке. Смотри на них, а не на HTML. HTML в `data/extracted/html/` нужен, только чтобы уточнить порядок блоков и найти текст, который не попал в REST.

**Проверка:**
- `data/extracted/url-map.json` содержит **ровно 10 путей**. Больше — останови работу, выведи лишние и спроси меня: значит на сайте есть страницы, которых нет в аудите, и это меняет карту редиректов.
- `content/materials/` содержит **8 файлов**.
- `public/legacy/media/` не пустой.

## Шаг 4. Выверка контента

Это самая важная часть задачи, и она ручная. Автоматика здесь ошибается.

1. Для каждого файла в `content/materials/` открой соответствующий HTML-референс и **сверь `specs[]` построчно** с таблицей на живой странице. Парсер работает по эвристике «первая ячейка — параметр, последняя — фактическое значение» и на нестандартной разметке промахивается. Сырые таблицы лежат в `data/extracted/specs-raw-*.html`.
2. Заполни `price.cashless` и `price.cash` — цифры на главной странице старого сайта. По состоянию на выгрузку: песок речной 430, песок обогащённый 1100, ОПГС 1100 безнал / 1000 нал, гравий 5-20 — 1200, гравий 20+ — 1100. **Сверь с реальной страницей**, а не доверяй этому списку: прайс правили в марте.
3. Заполни `applications[]` — где применяется материал, по тексту страницы.
4. Проставь осмысленные `shortTitle` (для меню и карточек) и `order`.
5. `alt` у фотографий — по смыслу изображения, на русском. Пустые `alt` недопустимы.

Всё, что вызвало сомнение, — строкой в `DECISIONS.md`.

**Проверка:** ни в одном материале не осталось `null` в `price` и пустых `specs[]`.

## Шаг 5. Вёрстка

Собери страницы согласно структуре из раздела 5 `PROMPT.md`, но **под старыми адресами**:

```
/                                              главная (одностраничник)
/nasha-produkcziya/                            список материалов
/opgs/  /pesok-rechnoj/  /gravij-...  и т.д.   8 карточек материалов
/politika/                                     новая, обязательна
```

Адреса пока старые — ЧПУ и 301 будут на Этапе 4. Не трогай их.

Что построить:
- `app/layouts/default.vue` — шапка, подвал, мобильная навигация. Меню — как на старом сайте: «Наша продукция» ссылкой, остальные пункты якорями на главной.
- Секции главной — отдельные компоненты в `app/components/section/`, контент из `content/pages/index.md`.
- `app/pages/[slug].vue` или явные файлы страниц для карточек материалов — на твоё усмотрение, реши и запиши в `DECISIONS.md`.
- `MaterialSpecTable` — полноценная таблица на десктопе, список «параметр → значение» на мобильном. Данные из `specs[]`, **не из HTML**.
- Мета-теги через `useSeoMeta` из поля `seo` каждого документа.
- `/politika/` — типовая политика обработки персональных данных по 152-ФЗ с реквизитами ООО «МИРУМИР». Данные юрлица мне ещё не передали: поставь плейсхолдеры вида `{{ИНН}}` и вынеси в `DECISIONS.md` отдельной строкой.

Формы заявки на этом шаге **не делай** — поставь заглушку с телефоном и ссылками на WhatsApp и Telegram. Форма это Этап 1.

**Проверка:** `pnpm build` проходит; каждая страница открывается; на мобильном 390px нет горизонтального скролла.
